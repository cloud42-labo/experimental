# 店舗生存サバイバルゲーム v6 仕様書 (GDD & PRD)
## 本書について
本書は、オープンデータ（e-Stat）の実データを活用し、10年後の人口動態や産業構造に抗いながら店舗を生存させる経営シミュレーションゲーム「未来の店舗生存サバイバルゲーム (v6)」のゲームデザインドキュメント (GDD) および製品要件定義書 (PRD) である。

ビジネス大方針を統一する「インセプションデッキ」と、エンジニアが迷わず実装できるレベルの「詳細設計・技術要件」を統合している。

## 第1部：インセプションデッキ (Inception Deck)

### 1. 我々はなぜここにいるのか (Why We Are Here)
日本の多くの地域において、人口減少、少子高齢化、そして深刻な人手不足が店舗小売・サービス業の息の根を止めつつある。
従来の「出店して終わり」という静的な商圏分析ツールでは、10年先の生存率を担保できない。
我々は、**「出店した店舗が10年後どう変化し、業績低下や採用難をどのような経営コマンド（ヒト・モノ・カネ）で克服し生き残るか」**を、実データ（e-Stat）に基づきリアルタイムに体感・学習できるゲームを提供するためにここにいる。

### 2. エレベーターピッチ (The Elevator Pitch)
*   **「出店して終わり」の静的な商圏分析ツールに課題を感じている**
*   **店舗小売業のオーナー、店舗開発担当、エリアマネージャー、または経営を学ぶ学生** 向けに、
*   **「未来の店舗生存サバイバルゲーム (v6)」** は、
*   **e-Statの町丁目レベルの実データ（国勢調査・経済センサス）と連携し、10年後の生存率とP&L（損益）推移を予測する経営シミュレーター** です。
*   これを使うことで、**「ターゲット客（モノ）」「働き方のシフト（ヒト）」「DX・財務（カネ）」** の3大経営要素がどう噛み合って生存率を激変させるかを、3D地図とインタラクティブな財務ダッシュボードで体感できます。
*   **単なる理論的な勉強会ツール** とは異なり、外部Cバイナリ（SpatiaLite）に依存しない完全ポータブル配布設計により、一般ユーザーがダウンロードしてダブルクリックするだけで自立動作する高度なパッケージを提供します。

### 3. パッケージデザイン (Product Packaging)
*   **キャッチコピー**: 「10年後の未来予測に立ち向かえ。e-Stat実データで挑む、究極の店舗生存サバイバル。」
*   **主要モジュール**:
    1.  **3D商圏サバイバルマップ**: 周辺メッシュの過疎化リスクや採用競合を危険色（赤）で可視化。
    2.  **インタラクティブP&L推移**: 10期（10年間）の損益、キャッシュ、返済金を毎期シミュレート。
    3.  **生存診断ダッシュボード**: 最終的な生存確率と、財務・運営の健全性をSSS〜Eのランクで辛口判定。

### 4. やらないことリスト (The NOT List)
*   **やること (IN)**:
    *   e-Stat API (v3.0, `searchKind=2`) からの国勢調査・経済センサスデータの取得。
    *   7つの異なる業種業態（新規「ペット関連小売」「金融事業」を含む）のミクロビジネスモデルの反映。
    *   標準SQLiteとJIS第3次メッシュの数理計算による、外部GIS拡張不要の超高速商圏サエリ抽出。
    *   「ヒト・モノ・カネ」の各経営コマンドによるPLおよび生存率のシミュレーション。
*   **やらないこと (OUT)**:
    *   GPS人流データのリアルタイム追跡（データコストが膨大になるため対象外）。
    *   実際の店舗レジデータの自動連携（汎用パッケージ化を優先）。
    *   3D都市モデル（PLATEAUなど）のフルロード（動作軽量化のため対象外、PyDeckメッシュで完結）。

### 5. 技術的な解決策 (Technical Solution)
*   **フロントエンド**: Streamlit + PyDeck による軽量3Dデータプロット ＆ D3.js互換のSVG rect軽量描画ロジック。
*   **バックエンド**: Python 3.12 + SQLite3（標準のB-Treeインデックスと数理座標判定）。
*   **配布形態**: 外部バイナリロードなし、ポータブルZIP + `起動する.bat` / `run.sh` によるワンクリック動作環境。

### 2. 「ヒト・モノ」の戦略適合度診断（実データのみで判定）

毎回の診断は、商圏内の実人口データ（e-Stat 国勢調査、2015年・2020年比較による実測年率）だけを使い、**円換算せず定性的に**「10年後、この戦略は人口動態に噛み合っているか」を評価する。競合店舗数・売上原価率など実データ化されていない要素には依存しない。

#### ① 【ヒト】客層とのマッチ度・採用のしやすさ
*   **客層とのマッチ度**:
    *   業種のターゲット適性重み（若年/現役/シニア）と、商圏内の実人口（3区分）を掛け合わせ、加重人口が10年間でどう変化するかを比率で見る。
    $$\text{客層マッチ度の変化率} = \frac{\sum_i w_i \cdot P_i(\text{10年後})}{\sum_i w_i \cdot P_i(\text{現在})}$$
    *   比率が1.1以上なら「良好」、0.9〜1.1は「横ばい」、0.7〜0.9は「注意」、0.7未満は「深刻」と定性判定する。
*   **採用のしやすさ**:
    *   依存する労働力層（例：若年層依存ならその実人口）が10年間でどう変化するかを同様に比率で見る。
    *   **【ヒトコマンド：主婦・シニア短時間シフト雇用】**
        *   効果：依存する労働力の定義を「現役層の一部＋シニア層」に切り替える。実データ上、シニア人口は増加傾向にあることが多いため、判定が改善しやすい。

#### ② 【モノ】商品ミスマッチ・DX投資
*   **商品の商圏ミスマッチ**:
    *   商圏内の実際の高齢化率（シニア人口 ÷ 総人口）が30%を超えているのに、業種プロファイルが「ファミリー・若者向け」のままだと、「商品ミスマッチのおそれ」という定性フラグを立てる。
    *   **【モノコマンド：小分け・シニアプレミアムフード特化】**
        *   効果：ミスマッチのフラグを解消し、客層マッチ度の評価を1段階改善する。
    *   **【モノコマンド：シニア向け相続・資産コンサル特化（金融事業のみ）】**
        *   効果：シニア層への適性重みを引き上げ、客層マッチ度の評価を改善する。
*   **施設へのDX投資**:
    *   **【モノコマンド：自動発注・セルフレジDX（コンビニ・スーパー・金融）】**
        *   効果：必要な労働力への依存度そのものを下げるため、「採用のしやすさ」の判定を実人口トレンドに関わらず1段階改善する。

#### ③ 【カネ】— v6.1で一旦削除
*   資金繰り・借入コマンドは、円建てP&Lの廃止に伴い一旦削除した。実データに基づく財務シミュレーションが可能になった際に再検討する。

### 3. 技術要件：空間データベースの高速矩形絞り込み（SpatiaLite不要設計）

一般ユーザーの環境で DLL や Cライブラリ（SpatiaLite）をインストールさせることなく、SQLite のインデックスだけで店舗半径 $R$ 内の地域メッシュ（JIS 3次メッシュ、1km四方）をミリ秒単位で抽出する。

#### ① テーブル定義（標準SQLite）
```sql
-- 1. 統計情報メタデータ
CREATE TABLE Stat (
    stat_id TEXT PRIMARY KEY,
    title TEXT,
    survey_date TEXT
);

-- 2. 統計値の格納
CREATE TABLE StatValue (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    stat_id TEXT,
    mesh_code TEXT,  -- JIS 3次メッシュコード（8桁の文字列、インデックス必須）
    value REAL
);
CREATE INDEX idx_statvalue_mesh ON StatValue(mesh_code);

-- 3. 属性値（年齢、世帯数区分など）
CREATE TABLE StatValueAttr (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    stat_value_id INTEGER,
    attr_name TEXT,
    attr_value TEXT
);

-- 4. SpatiaLiteの代わりに緯度経度の「バウンディングボックス」を通常の数値として持つ
CREATE TABLE MapArea (
    mesh_code TEXT PRIMARY KEY,
    min_lat REAL,
    min_lon REAL,
    max_lat REAL,
    max_lon REAL
);
CREATE INDEX idx_maparea_coords ON MapArea(min_lat, max_lat, min_lon, max_lon);
```

#### ② 数理座標計算（JIS第3次メッシュ規格）
8桁の3次メッシュコード（例：`53394611`）から、その四隅の緯度経度を数式で決定的に逆算する：
```python
def mesh_code_to_bbox(mesh_code):
    mesh_code = str(mesh_code)
    # 第一次基準メッシュ (2桁, 2桁)
    p = int(mesh_code[0:2])
    u = int(mesh_code[2:4])
    # 第二次基準メッシュ (1桁, 1桁)
    q = int(mesh_code[4])
    v = int(mesh_code[5])
    # 第三次基準メッシュ (1桁, 1桁)
    r = int(mesh_code[6])
    w = int(mesh_code[7])
    
    # 緯度（南端）
    lat_south = (p * 40 / 60) + (q * 5 / 60) + (r * 30 / 3600)
    # 経度（西端）
    lon_west = (u + 100) + (v * 7.5 / 60) + (w * 45 / 3600)
    
    # メッシュの幅
    lat_width = 30 / 3600  # 約30秒 (約900m)
    lon_width = 45 / 3600  # 約45秒 (約1125m)
    
    return {
        "min_lat": lat_south,
        "min_lon": lon_west,
        "max_lat": lat_south + lat_width,
        "max_lon": lon_west + lon_width
    }
```

#### ③ 空間クエリ（インデックス活用矩形絞り込み）
店舗の位置 $(Lat_0, Lon_0)$ から半径 $D$ km（緯度差 $\Delta Lat$, 経度差 $\Delta Lon$）の矩形サークルを、以下のSQLで瞬時に高速抽出する。
```python
delta_lat = D / 111.0  # 1度≒111km
delta_lon = D / (111.0 * math.cos(math.radians(Lat_0)))

query = """
SELECT MapArea.mesh_code, min_lat, min_lon, max_lat, max_lon 
FROM MapArea
WHERE min_lat <= ? AND max_lat >= ?
  AND min_lon <= ? AND max_lon >= ?
"""
# バインドパラメータ
params = (Lat_0 + delta_lat, Lat_0 - delta_lat, Lon_0 + delta_lon, Lon_0 - delta_lon)
```
これによってSpatiaLiteなしで、完全自立型の超高速な商圏抽出空間クエリを担保する。

### 4. フロントエンド描画要件：SVG rect軽量描画

D3.js等で地図上に1,000個以上のメッシュ（Polygon）を描画する際、SVGの `<path d="M...Z">` を大量に描画するとレンダリング速度が大幅に低下する。
地域メッシュは必ず完全な「長方形」であるため、SVGの **`<rect>`（矩形）要素** で描画することで、DOM処理の負荷を10分の1に激減させる。

```javascript
// D3.jsによる軽量描画実装例
const projection = d3.geoMercator().fitSize([width, height], geojson);

svg.selectAll("rect.mesh")
   .data(geojson.features)
   .enter()
   .append("rect")
   .attr("class", "mesh")
   .attr("x", d => {
       const bbox = d.properties.bbox; // 四隅の緯度経度
       return projection([bbox.min_lon, bbox.max_lat])[0];
   })
   .attr("y", d => {
       const bbox = d.properties.bbox;
       return projection([bbox.min_lon, bbox.max_lat])[1];
   })
   .attr("width", d => {
       const bbox = d.properties.bbox;
       const x1 = projection([bbox.min_lon, bbox.max_lat])[0];
       const x2 = projection([bbox.max_lon, bbox.max_lat])[0];
       return Math.abs(x2 - x1);
   })
   .attr("height", d => {
       const bbox = d.properties.bbox;
       const y1 = projection([bbox.min_lon, bbox.max_lat])[1];
       const y2 = projection([bbox.min_lon, bbox.min_lat])[1];
       return Math.abs(y2 - y1);
   })
   .attr("fill", d => colorScale(d.properties.riskValue))
   .attr("opacity", 0.7);
```

本書に定義された各業態のPL、e-Stat空間マージアルゴリズム、および描画要件をベースに実装されたプログラムは、迷いなく完璧な動作性能を担保する。
