# 未来の店舗生存サバイバルゲーム — ファシリテーションガイド（講師用進行台本）

対象: 店長候補研修でのPoC実施（受講者10〜20名、1〜2社想定）
対象バージョン: 開発版（`index.html` 2026-10-03時点、`APP_VERSION 0.14.1`）
Notion: `BUS-04-S03-T03b`

> このガイドは講師（ファシリテーター）がPoC当日にそのまま読み上げ・進行できる台本です。
> エンドユーザー向けの操作説明は [deliveries/v0.9.0/はじめてガイド.md](deliveries/v0.9.0/はじめてガイド.md) を参照してください
> （本ガイドは「どう進行するか」、はじめてガイドは「どう操作するか」の役割分担）。
> アプリ本体は開発以降も変わるため、実施前に本ガイド冒頭の対象バージョンと、
> 実際に配布する `index.html` の `APP_VERSION` が大きくズレていないか確認してください。

## 1. この研修のねらい

「出店して終わり」ではなく、**人口動態の変化に対して経営判断を更新し続けられるか**を
店長候補自身に体感させることが目的です。正解を教えるのではなく、「③の診断結果を見て、
④の経営判断がなぜ妥当／筋が悪いと評価されたか」を自分の言葉で説明できる状態を
ゴールとします。

## 2. 事前準備（講師がPoC開始前に行うこと）

- [ ] **e-Stat アプリケーションID**を講師自身で1つ取得しておく（[はじめてガイド.md](deliveries/v0.9.0/はじめてガイド.md)の「事前準備」参照）。個人のPCで操作を見せるデモ用に1つあれば足りる。受講者が各自のPCで操作する場合は、受講者ごとに事前取得を依頼するか、研修用に共有IDを1つ用意し投影画面にだけ映す（IDは画面共有時に映り込ませない）。
- [ ] 受講者の人数分の実施形態を決める（下記3.参照：個人プレイ／ペア・チームプレイ）。
- [ ] 受講者に事前課題として「診断したい自社店舗（または身近な店舗）の所在地」を1件決めてきてもらう。決められない受講者向けに、講師側で予備の店舗所在地・業種を2〜3件用意しておく。
- [ ] 投影環境（プロジェクター・画面共有）と、受講者が個別に操作する場合はブラウザが動くPC/タブレットを人数分確保する。
- [ ] 振り返りシート（6.の問いを印刷またはNotion/Google Formsに用意）。

## 3. 実施形態の決め方

| 人数 | 推奨形態 |
| :--- | :--- |
| 10名以下、1社 | 個人プレイ（1人1台）＋全体振り返り |
| 10〜20名、1社 | 3〜4人のチームプレイ（1チーム1台、相談しながら合意形成）＋チーム発表 |
| 20名・2社混在 | チームプレイを会社ごとに分け、最終振り返りは会社混成グループで実施（他社の経営判断との違いを比較させる） |

チームプレイを推奨する理由: ④の経営判断は「保全・改装・商圏拡大・競合を叩く・撤退」の
5択を**見比べて選ぶ**設計になっており、チームでの合意形成そのものが店長候補の研修価値になる。

## 4. タイムテーブル（標準90分、個人/チーム共通）

| 時間 | 内容 |
| :--- | :--- |
| 0:00–0:10（10分） | 導入：ねらいの説明、5.の進行台本どおりに口頭説明 |
| 0:10–0:20（10分） | 起動・店舗設定：場所入力、業種選択、店舗プロファイル入力（任意）、データ取得 |
| 0:20–0:30（10分） | 画面の見方の解説（①〜④を1周、講師が自分の画面で実演しながら） |
| 0:30–0:70（40分） | プレイ本番：⑤「期を進める」を使い、0→3年目→6年目→10年目まで3回の意思決定ループを回す（1ループ約12〜13分が目安） |
| 0:70–0:85（15分） | 振り返り（6.の問いに沿って、まずチーム内→その後全体共有） |
| 0:85–0:90（5分） | クロージング：講師まとめ |

人数が多く個別サポートに時間を要する場合は、起動・店舗設定に+10分の予備を見込む
（120分版にする場合はここと振り返りを拡張する）。

## 5. 進行台本（読み上げ用）

### 5-1. 導入（0:00–0:10）

> 「これから、実際の人口統計データを使って、皆さんの店舗が10年後どうなるかを
> シミュレーションするツールを使います。これは『当てる』ゲームではありません。
> 今の経営判断が、これから変わっていく人口動態と噛み合っているかどうかを、
> 実データをもとに診断するツールです。
>
> 大事なのは正解を当てることではなく、『なぜその経営判断が妥当、あるいは筋が悪いと
> 診断されたのか』を自分の言葉で説明できるようになることです。」

ここで、7業種（コンビニ・食品スーパー・居酒屋 等）のうちどれが今日の題材か、
事前課題で決めてきた店舗所在地を使うか、講師用意の予備ケースを使うかを明示する。

### 5-2. 起動・店舗設定（0:10–0:20）

1. `index.html` を開く（事前に配布済み、またはこの場でUSB/共有フォルダから渡す）。
2. 所在地を入力（Google Mapsの座標貼り付け、またはURL貼り付け、または緯度経度直接入力の
   いずれでも可）。
3. 業種を選択（必須）。
4. 店舗プロファイル（年間売上高・粗利額・販管費、正社員数・パート/アルバイト数、築年数）は
   **できれば入力させる**。実在店舗に近い数値を入れるほど④の経営判断評価がリアルになる。
   わからない場合は未入力のまま進めてよい（0として扱われる旨を伝える）。
5. e-StatアプリケーションIDを入力し、「データを取得して開始する」を押す。

> 進行上の注意: ここで複数チームが同時にe-Stat APIを叩くため、数秒〜数十秒の
> 待ち時間が発生する。待ち時間中に次の5-3.の画面説明を始めてよい。

### 5-3. 画面の見方（0:20–0:30、講師が自分の画面で実演）

画面は「左＝いまの状況」「右＝どうするか」で構成されている。①〜④の順に実演する。

1. **①10年後の人口予測** — 商圏内の年少・生産年齢・老年人口が今後どう変わるかを地図と
   グラフで見せる。「この商圏は10年後、働き手の年代がどう変わりそうですか？」と問いかける。
2. **店舗プロファイル** — 入力した内容の確認。「編集」からいつでも業種・数値を変更できる。
3. **②ヒト・モノ・カネ** — 業種に応じた対策コマンド（例: 主婦・シニア短時間シフト雇用、
   自動発注・セルフレジDX）をON/OFFできる。**一度ONにした施策は以後OFFに戻せない**
   （「一度打った手は取り消せない」という設計上の前提）ことを必ず伝える。
4. **③診断結果** — 客層とのマッチ度・採用のしやすさ・パートスタッフの充足見込みを
   「良好／注意／深刻」の3段階で表示する。
5. **④経営判断を下す** — 「保全・現状維持／改装する／商圏を拡げる／競合を叩く／撤退する」の
   5択を**常時見比べながら**選ぶ。それぞれが③の診断結果と店舗プロファイルをもとに
   「妥当／要検討／筋が悪い」と評価される。

### 5-4. プレイ本番（0:30–0:70、3年→6年→10年の3ループ）

⑤「期を進める」セクションを使い、以下を**3回**（3年目・6年目・10年目）繰り返す。
1ループの目安時間は約12〜13分。

各ループで講師が投げかける問い（チームで話し合わせてから次へ進む）:

1. 「③の診断結果は、前の期と比べて良くなった？悪くなった？」
2. 「②のヒト・モノ・カネのうち、何か手を打つ？ それとも様子見する？」
   （打つ場合は、ONにすると以後戻せないことを再確認させる）
3. 「④の5択のうち、どれを選ぶ？ なぜその判断が今の診断結果に対して妥当だと思う？」
4. 「次の期へ」を押す前に、チームとしての結論（②で何をしたか／④で何を選んだか／理由）を
   一言でメモさせる（振り返りで使う）。

3回目（6年目→10年目）を終えると「10年目に到達しました」という画面になる。
これが本編プレイの終了地点。

> 途中で「撤退する」を選ぶと、その時点でゲームが終了する設計になっている。
> チームが撤退を選んだ場合は、無理に続けさせず「なぜ撤退という判断に至ったか」を
> そのチームの振り返り素材として扱う。

### 5-5. 振り返り（0:70–0:85）

6.の問いを使い、まずチーム内（5分）→全体共有（10分）の順で進める。
2社混在の場合は、最終振り返りは会社混成グループで行い、他社チームとの経営判断の
違いを比較させる。

### 5-6. クロージング（0:85–0:90）

> 「今日は『当たり外れ』ではなく、『診断結果と経営判断が噛み合っているか』を
> 体感してもらいました。明日から、皆さんの実店舗でも、①〜④と同じ順番——
> 今の状況を見る→対策を考える→診断する→判断する——を意識してみてください。」

## 6. 振り返り問い

### 各期ごと（5-4.で使用、再掲）

1. 診断結果（③）は前の期からどう変わったか。
2. ②で何を選び、何を見送ったか。その理由は。
3. ④でどの経営判断を選び、それはなぜ妥当／要検討／筋が悪いと評価されたか。

### 最終振り返り（0:70–0:85で使用）

1. 10年間を通じて、一番効いた（あるいは効かなかった）経営判断はどれだったか。
2. 「一度打った手は戻せない」という制約は、実際の経営判断とどう似ている／違うと感じたか。
3. このゲームの診断ロジックで、自社の実店舗と重なると感じた点・重ならないと感じた点は。
4. 撤退を選んだ（または選ばなかった）チームは、その判断の決め手は何だったか。
5. （2社混在の場合）他社チームの経営判断を見て、自社との違いで気づいたことは。

## 7. よくあるトラブルと対応（講師向け）

- **「データ取得に失敗しました」と出る** — まずe-Stat IDの貼り付けミスを確認させる
  （[はじめてガイド.md](deliveries/v0.9.0/はじめてガイド.md)「よくある質問」参照）。
  複数チーム同時アクセスでAPI側が混雑している場合は、数十秒おいて再試行させる。
- **場所をうまく指定できない** — 緯度経度直接入力（例: `35.6812, 139.7671`）に切り替えさせる。
  事前に講師用の予備ケース（所在地・業種）を配っておくと迷いを防げる。
- **山間部・海上など人口データが無い場所を指定してしまった** — 近くの市街地に変更させる。
- **チームで②③④の数値の意味が噛み合わず進行が止まる** — 5-3.の実演画面に戻り、
  講師の画面を再度見せながら該当箇所だけ再説明する。無理に全チーム足並みを揃えず、
  進みの早いチームには「もう一周、違う経営判断を試す」よう促してよい。
- **時間が足りず3ループ終わらない** — 2ループ（6年目まで）で打ち切り、振り返りの問いは
  「6年目時点で」に読み替えて進行する。10年目到達は必須条件ではない。
