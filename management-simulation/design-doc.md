## ⚙️ 会計エンジンの構造

- B/S恒等式：資産（現金＋在庫＋固定資産＋保証金）＝負債（買掛＋設備未払＋借入）＋純資産（資本金＋利益剰余金）
- 全構成・借入あり/なしで期末B/S差0円を検証済み（Node.jsで実コード実行）
- 在庫は加重平均原価法（invBase/inv）で評価損も正確に計算
- 月次P/L（plHistory）とC/F（cfHistory）は12ヶ月分蓄積し決算画面で表示
- 借入：与信枠 ＝ 自己資金 × 2.5 ＋ 信用度ボーナス（〜3.5倍まで拡大）。申請翌月着金。

## 🎲 イベントシステム

| イベント | kind | 発生月 | 効果 |
|---|---|---|---|
| 台風・猛暑 | salesHit | 5・8月 | 売上一時ダウン（脆さ係数で増幅） |
| 中核スタッフ退職 | staff | 6・9月 | staffShortage=3。売上18%→12%→6%減（3ヶ月回復） |
| SNSバズ | salesHit（正） | 7・11月 | 売上一時アップ |
| 主要設備が故障 | equipHit | 7・10月 | 修理費ゼロ（保証期間内）。equipShortage=1で売上20%減×1ヶ月 |
| 在庫評価損 | invHit | 8・11月 | 在庫 × wdRisk × 在庫過剰係数が損失に |
| 取引先離脱 | salesHit | 6・10月 | 売上ダウン（脆さ係数で増幅） |
| 仕入先倒産 | supplyHit | 5・9月 | 代替手配コスト80万×脆さ係数。supplyShortage=2で売上15%→7%減 |

## 🚧 既知の課題・今後の課題

- **複数年プレイ（2期目以降）**：現在は1期12ヶ月のみ。採算構造の蓄積が体験できない。2期目以降は店舗拡大（梅→竹→松）や撤退判断を実装し、ダイエー・マイカル・ヤオハン型の「拡大失敗」パターンを体験できるようにする
- **モバイル最適化**：スマホでは右パネルの財務三表が見づらい場面がある
- **イベントの脆さ係数**：現金の薄さによる増幅のみ。在庫・借入比率との複合は未実装
- **長期借入（信用度50以上で解放）**：翌々月着金のロジックだが、プレイヤーへの案内が不十分
- **人件費の現実化**：60坪・店長1人＋パート3人想定で月80万円前後が妥当。現在の110万円は見直し候補
- **役員報酬**：現状は人件費に含まれていない。固定費への組み込みを将来的に検討
- **P/L拡充（経常利益・法人税・純利益）**：現状は営業利益止まり。本来のP/Lは以下の構造を持つ。実装する場合は段階的に行う。ランク判定基準も税引後純利益ベースへの変更が必要。
  ```
  営業利益
  　- 支払利息（借入残高 × 金利）
  = 経常利益
  　- 特別損失（在庫評価損を分離）※現状は売上原価に吸収
  = 税引前当期純利益
  　- 法人税等（800万以下21%・超34%の2段階実効税率、赤字時ゼロ、繰越欠損金は省略）
  = 当期純利益 → 利益剰余金に加算
  ```
  評価損の分離はB/S恒等式に影響するため、変更後は全構成での整合性再検証が必須。
- **EBITDAの表示**：減価償却費を足し戻した「現金創出力」の指標。設備規模が異なる梅/竹/松の収益力比較や、借入返済能力の可視化に有効。`EBITDA = 営業利益 + 減価償却費`。決算画面の経営数値分析への追加を検討。

## 🔢 バージョン番号のルール

セマンティックバージョニング（`MAJOR.MINOR.PATCH`）に準拠する。桁数制限なし。

| 桁 | 上げるタイミング | 例 |
|---|---|---|
| MAJOR | 別ゲームレベルの破壊的変更（会計エンジンの全面刷新など） | `0.x.x` → `1.0.0` |
| MINOR | 機能追加・新画面・新指標の追加 | `0.9.x` → `0.10.0` |
| PATCH | バグ修正・文言変更・UIの微調整 | `0.9.6` → `0.9.7` |

変更後は `index.html` 冒頭の `APP_VERSION` を必ず更新すること。

**正式リリースへの昇格：** プロダクトオーナーが正式リリースを宣言したタイミングで `v1.0.0` に上げる。それまでの `0.x.x` はすべてプレリリース扱い。
→ **2026-08-08、プロダクトオーナーの承認を得て `v1.0.0` に昇格済み。**

## 📁 リポジトリ管理ルール

### ファイル構成

| ファイル | 用途 |
|---|---|
| `index.html` | 開発用ソース（JSX + Babel standalone） |
| `index.dist.html` | 配布用（JSXを事前コンパイル済み・Babel不要） |
| `deliverables/vX.X.X/` | バージョンごとの配布物スナップショット |

### index.html と index.dist.html の使い分け

- **開発・編集**は `index.html` で行う
- スクリプトが500KBを超えるためブラウザのBabel変換が失敗する。受講生への配布・動作確認は必ず `index.dist.html` を使うこと
- コードを変更したら必ず `index.dist.html` を再生成してコミットする

#### index.dist.html の再生成手順

```bash
node -e "
const fs = require('fs');
const Babel = require('/tmp/node_modules/@babel/standalone');
const html = fs.readFileSync('index.html', 'utf8');
const scriptMatch = html.match(/<script type=\"text\/babel\">([\s\S]*)<\/script>\s*<\/body>/);
const result = Babel.transform(scriptMatch[1], {
  presets: [['react', {runtime: 'classic'}]],
  filename: 'app.js'
});
let newHtml = html
  .replace('<script src=\"https://unpkg.com/@babel/standalone/babel.min.js\"></script>', '')
  .replace(/<script type=\"text\/babel\">([\s\S]*)<\/script>(\s*<\/body>)/, '<script>' + result.code + '</script>\$2');
fs.writeFileSync('index.dist.html', newHtml, 'utf8');
"
```

### deliverables/ の運用ルール

- リリース時に `deliverables/vX.X.X/` フォルダを作成し以下の4点を格納する
  - `index.html`（開発用ソース）
  - `index.dist.html`（配布用）
  - `はじめてガイド_vX.X.X.docx`
  - `リリースノート_*.docx`
- `deliverables/` 直下にはファイルを置かない（必ずバージョンサブディレクトリに入れる）
